# 风格登记表

风格预设是**变量集**（配色/字体/背景/装饰），不改变 `assets/core.css` 的引擎不变量。
每次第 3 步先查本表：命中 → 让用户选；未命中 → 按第 3.3 节新建并登记。

## 预设 Schema（新建风格必须包含）

```markdown
# <名称>（<slug>）

## 适用 / 不适用
## 调性关键词
## 色板（:root 变量块，可直接粘贴）
## 字体（display / body / mono，附 Google Fonts 链接）
## 背景与封面偏好（flat / tint / dark；封面模板）
## 装饰语言（要不要贴纸/图标/纹理；用多少）
## Do / Don't（含本风格豁免项）
## 参考来源（若来自小红书调研，记录样本与共性）
```

**必须满足的硬约束**（所有风格）：单卡 ≤3 色；一个 accent + 一个 highlight；主色 70% / 强调 30%；禁止霓虹/渐变文字/纯黑底大字；层级步进 ≥1.25×。

## 新建风格方法（小红书调研）

当用户要一个**没做过的风格**时：

1. **检索**：在小红书搜索该风格高赞/高流量笔记（关键词：风格词 + 领域词；如"科技 小红书 封面""手账 排版"）。
2. **取样 20 篇同风格高分笔记**（单篇易误判）。
3. **按维度归纳共性**：
   - 封面：构图、底色、字体、文字叠加方式
   - 配色：主色/强调色/中性色（取近似 hex）
   - 字体：标题体/正文字体
   - 结构：信息密度、留白、装饰
   - 情绪：适合的内容类型
4. **产出预设草案**（按上方 Schema），**先给用户确认**。
5. 确认后：写入 `references/styles/<slug>.md`，并在本表登记。
6. 预设只填**变量**；若现有组件无法承载该风格的结构，先读 `design-system.md`，**只加组件、不改不变量**。

> 注意：不要把"平台原生"误判为风格（emoji/大字/标签是小红书通用，不是某种风格）。
