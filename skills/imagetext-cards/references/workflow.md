# 工作流细则

六步流程的完整话术、判定与产出格式。SKILL.md 只给概览，细节以本文件为准。

---

## Step 1 · 收素材（强制）

**输入**：用户提供的博客文章、草稿、大纲、或一段内容说明。

**动作**：
- 读取素材，落地到输出目录的 `source.md`（原文保留，便于追溯）。
- 从素材中抽取：主题、核心观点、关键事实与数字、可用的截图/图源。

**判定**：
- 若用户未提供任何素材 → **停止**，明确索要："请先把要改写的文章/草稿发给我（文件路径或内容都可以）。"
- 素材残缺（只有标题）→ 追问核心要点，不自行补全事实。

**产出**：`<out>/source.md` + 一份内部要点清单（主题 / 3–6 个核心信息 / 事实与数字 / 可选图源）。

---

## Step 2 · 补充内容与风格（一次性问清）

**把「补充内容」和「风格」合并成同一条消息**，避免多轮打断：

> 开始前一次确认（都可跳过）：
> 1. **素材补充**：有没有官方文档 / 参考资料要一起读？有没有图片素材，或需要我去找配图？要不要对文中的事实/数字做交叉校验？
> 2. **风格**：想要什么风格？（例如 科技 / 手账 / 好物分享 / 极简 / 杂志感……）
>    —— 命中已有预设我会直接列给你选；没做过的风格，我会先调研目标平台同风格高分笔记，再给你一份预设草案确认。

**处理**：
- 官方文档 → 读入并归并到要点清单。
- 图片需求 → 调用 `Skill(image-sourcing)`；用户自备素材则归入 `src/assets/`。
- 事实校验 → 调用 `Skill(source-verify)`：对关键事实交叉验证，**把 `[unverified]` / `❌ 争议` 的事实挡在卡片文案之外**（硬规则 4）；矛盾事实用更权威来源，必要时加"据称"。
- 风格 → 交给 Step 3 的分支逻辑处理。

> 用户有权跳过；但**若素材含事实性数字且用户未选校验**，在出图前主动提醒一次："文中 X 个数字建议先做一次校验，要继续吗？"

---

## Step 3 · 确定风格（关键分支）

### 3.1 风格问题已在 Step 2 一并问出
此处只处理用户回应并进入分支，**不重复提问**。

### 3.2 判定是否做过
查 `references/styles/_index.md` 登记表：

- **命中已有风格** → 列出该风格 + 其它可选预设，让用户**选择**。直接加载对应 `<style>.md`。
- **未命中** → 走 3.3 新建。

### 3.3 新风格：调研 → 总结 → 确认 → 登记
按用户方法执行：
1. 在目标平台（小红书 / 微信贴图号）检索该风格的**高流量 / 高赞**笔记（封面、配色、字体、结构、文案）。
2. 分析共性，总结成一份**风格预设草案**（结构见 `styles/_index.md` 的 Schema）。
3. **先给用户确认**（推荐，避免登记错误风格）。
4. 确认后写入 `references/styles/<slug>.md`，并在 `_index.md` 登记。

> 预设只提供**变量**（色板/字体/背景/装饰）与 do/don't；不得改动 `core.css` 的引擎不变量。

### 3.4 产出
选定/新建的 `<style>.md` → 提取其 `:root` token 块 + 字体引用 + 封面偏好。

---

## Step 4 · 生成卡片

### 4.1 选叙事骨架
从 `references/content-templates.md` 选一：种草测评 / 教程攻略 / 清单合集 / 对比 / 避坑排雷 / 个人故事复盘。

### 4.2 拆分卡片
按 8 图骨架：`钩子 → 核心观点 → 分点(3–4) → 案例/数据 → 总结 → CTA`（6–8 张，宁少勿凑）。
每张：**一个观点**、≤60 字、短句、封面 3 秒说清价值。

### 4.3 大纲确认（条件项）
- **必做**：卡数 ≥6，或采用**新风格**，或内容涉及多个数字/事实。
- **可跳过**：内容很短（3–4 卡）且沿用既有系列风格与结构时。

先输出**标题候选 + 每图要点**，确认/调整后再出图：

```
标题候选：1) … 2) … 3) …
封面：<封面文案>
02 | <标题> | <要点>
03 | <标题> | <要点>
…
08 | CTA | <行动 + 评论区引导>
```

### 4.4 生成
- 复制 `assets/core.css` → `<out>/src/core.css`。
- 复制 `assets/post-template.html` → `<out>/src/postN.html`，替换 `:root` 为预设 token，填充全部 `<!--REPLACE-->`。
- 素材（logo、截图）放 `<out>/src/assets/`，相对引用。
- 按 `references/export-and-qc.md` 导出 PNG 到 `<out>/cards/postN/`。
- 写笔记文案：标题候选（15–25 字）+ 正文（100–300 字、短句、emoji 功能化）+ 话题标签（大词+精准词+系列词）+ 发布时间建议。

---

## Step 5 · 反 AI 味自检（只给建议）

按 `references/anti-slop.md` 的自检清单逐条核对，输出**建议报告**。**不改任何文件。**

报告格式：
```
## 反 AI 味自检（建议）

真该改：
  1. [卡片/位置] 问题 —— 为什么像 AI —— 建议：…
  2. …

本风格豁免（保留，仅告知）：
  - [卡片/位置] 某项 —— 属于该风格刻意选择，保留。
  - …

结论：共 N 条建议，其中 M 条建议采纳。要按哪些改？
```

必须区分两类：**真该改** vs **本风格豁免**（豁免项来自预设的 do/don't + `anti-slop.md` 豁免清单）。

---

## Step 6 · 确认后修改

- 用户勾选要采纳的建议。
- **只修改确认的项**：改 `src/*.html` 或 `core.css` 的对应组件；文案类改动可先过 `Skill(humanize-plus)`。
- **只重导出受影响的卡片**，不整套重做。
- 记录本次豁免项（写入输出目录 README 的"风格说明"），下次不重复报。

---

## 异常处理

| 场景 | 处理 |
|------|------|
| 无素材 | 停止，索要素材 |
| 素材含未验证数字且用户不做校验 | 提醒一次；仍不做则数字不进卡片或标"待补" |
| 用户选未做过的风格 | 走 3.3 调研→草案→确认→登记 |
| 引擎组件不够用 | 先读 `design-system.md`；**只加组件、不改不变量**，并同步到 `core.css` |
| 卡片超过 8 张 | 拆成两篇（系列），不硬塞 |
| 无真实截图 | 用最小 `.mock` 概念图，并告知用户这是示意；不用重画的 OS/浏览器 chrome |
